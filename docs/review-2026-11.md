## High

### H1. The updater runs a download it never verifies
`src/features/update.rs:536-572` (`fetch`), `src/features/update.rs:650-672` (`install`).
The release job writes `SHA256SUMS.txt` beside the assets
(`.github/workflows/release.yml`, step "Checksums"), but the app downloads the `.exe` over the
proxy, checks only that it is over 1 MB, swaps it in for itself and spawns it. A proxy or a
captive portal that answers 200 with any body over 1 MB replaces the program with that body.
TLS is rustls, so a plain MITM is out, but a corporate proxy that terminates TLS is exactly
the environment this app runs in.
**Fix:** download `SHA256SUMS.txt` from the same release, hash the staged file and refuse to
install on a mismatch. Also verify the PE signature on Windows once the build is signed.

### H2. A flood of output is drained whole into one frame
`src/pty/session.rs:280-298` (`drain_events`), `src/pty/telnet.rs:437` and
`src/pty/session.rs:153` (unbounded channels), `src/app/tab.rs:710-745` (`pump`).
The reader threads push every chunk into an unbounded channel; `pump` drains all of it and
feeds the parser, the log and the decoder in the same frame. `zw ^BigGlobal` on a fast local
instance, or a minimised window reopened after an hour of chatty output, means one frame
that parses tens of megabytes while the UI is frozen, and a channel that grew without bound
while nothing drained it (the frame loop does not run when the window is hidden).
**Fix:** cap the bytes taken per frame (say 256 KB), leave the rest in the channel and ask
for another frame; use a bounded channel so the reader thread blocks instead of the process
growing. Measure with `paint_cost` before and after.

### H3. Settings and themes are written in place, not atomically
`src/config/mod.rs:971` (`Settings::save`), `src/config/mod.rs:1167` (`save_theme`),
`src/features/history.rs:150` (`History::save`).
`std::fs::write` truncates then writes. A crash, a full disk or a power cut between the two
leaves an empty `settings.toml`, and the next start comes up with defaults, as if the user
had never configured anything. The legacy migration at `src/config/mod.rs:92-112` already
does it right (staging folder, then rename).
**Fix:** one `write_atomic(path, bytes)` helper in `config/` (write `path.tmp`, `sync_all`,
rename over) used by every save. Keep the previous file as `.bak` for settings.

### H4. Nothing runs on a push or a pull request
`.github/workflows/release.yml:6-7` says so. PR #8 and #9 merged with no check at all; the
test job only runs on a tag, so a broken `main` is found at release time, as the macOS
runner retirement was.
**Fix:** a second workflow, `ci.yml`, on `pull_request` and `push: branches: [main]`, with
the same five commands from CLAUDE.md on `ubuntu-latest` only (the cheapest runner), with
`Swatinem/rust-cache`, `timeout-minutes: 30`, and `concurrency` cancelling older runs of the
same PR. Mark it required in the ruleset. Keep the three-platform matrix for tags.

### H5. Plugins run with no fuel, memory or time limit
`src/plugins/host.rs:93` (`Engine::default()`), `:98` (`Store::new` with no limiter).
A plugin with an infinite loop in `nit_on_output` hangs the UI thread for good; one that
grows its memory takes the machine. Plugins are behind a feature flag today, but the host is
the seam everything later goes through.
**Fix:** `Config::consume_fuel(true)` with a fuel budget per call, or `epoch_interruption`
with a timer thread; `StoreLimits` with a memory cap; a plugin that trips either is unloaded
with a status message.

### H6. The `.exe` is swapped and spawned from a path the user controls
`src/features/update.rs:509-520` and `:650-672`.
The staged file is written beside the running executable, which is wherever the user put
it, often a shared or a Downloads folder. Combined with H1, anything that can write beside
the program decides what runs next. The rename dance is right; the trust in the content is
the problem. Fixing H1 covers it; mention here so the two are done together.

### H7. CRLF is not pinned, and the repo warns on every commit
`.gitattributes` has only `*.sh text eol=lf`. Every `git add` prints twenty "LF will be
replaced by CRLF" warnings, and a checkout on Linux versus Windows differs for every file.
The PowerShell files carry a BOM on purpose (`examples/doctor-selftest/powershell/*.ps1`),
which is fine, but the line endings are whatever the last editor wrote.
**Fix:** `* text=auto eol=lf`, `*.ps1 text eol=crlf`, `*.png binary` (and the other assets),
then one normalising commit (`git add --renormalize .`).

### H8. There is no `LICENSE` file
`Cargo.toml:6` says `license = "MIT"`; the repository has no `LICENSE` or `LICENSE-MIT`.
The packaged zip and AppImage ship a program whose licence exists only as a Cargo field.
**Fix:** add `LICENSE` (MIT, company as holder) and include it in `packaging/windows/package.ps1`'s
zip and the Linux tar.

## Medium

### M1. The window title from OSC is unbounded and unsanitised
`src/term/parser.rs:168-176`. A remote host can set a title of any length, with control
characters, and it goes straight into the title bar and the tab strip. Not dangerous, but a
megabyte title is one allocation per frame in the chrome.
**Fix:** cap at ~256 chars, strip C0/C1 controls, in `osc_dispatch`.

### M2. Autocomplete, doc lookup and the glyph cache have no bounds *(to confirm)*
`src/features/autocomplete.rs` (2111 lines, learns from every command), `src/features/doc_lookup.rs`
(2834 lines), `src/ui/terminal_view/glyphs.rs:46-80` (one galley per distinct char/font).
A session that prints every Unicode glyph, or a year of learned commands, grows these
without a ceiling. Check each for a maximum and an eviction policy; the glyph cache at least
should drop entries when the font changes (it may already).

### M3. The doctor runtime attacks run in the normal test suite
`src/features/doctor/adversarial_kinds.rs` spawns `python`, `powershell` and `bash` for 30 of
its 40 tests; the suite went from ~9 s to ~19 s. They are also the only tests that depend
on what is installed on the machine.
**Fix:** `#[ignore]` them behind the same gate as `selftest_pack`, or a `CONSISTERM_SLOW_TESTS`
env var, and run them in the tag workflow's test job explicitly.

### M4. `Doctor::poll` is called from the sidebar every frame
`src/ui/settings_view/mod.rs:833`, `src/features/doctor/mod.rs:222`. It is a `try_recv`
loop, so it costs nothing when idle, but it is a poll in a codebase whose rule is "nothing
is polled": the worker already calls `pty::wake()`, so the drain belongs in `App::update`
with the other event drains, not in a widget. Also, the light shows the stale result after
the checks file changes until Settings is opened.

### M5. The release workflow pins images that age out
`.github/workflows/release.yml:105` (`ubuntu-22.04`, chosen for glibc 2.35; GitHub retires
20.04-style images about two years after the next LTS), `:147` (`macos-14`, retired, PR #9
moves it to `macos-15`), `actions/checkout@v4` warns about Node 20 on every job. There is no
`timeout-minutes` on any job, so a hung notarization holds the runner for six hours.
**Fix:** `timeout-minutes` on every job; a calendar note (or a Dependabot `github-actions`
entry in `.github/dependabot.yml`) so action majors and images move before they are removed;
for glibc, consider building Linux in a container (`ubuntu:22.04` image on `ubuntu-latest`),
which outlives the hosted image.

### M6. `build.rs` panics instead of failing
`build.rs:9` `res.compile().unwrap()`. Without `windres` on `PATH` the message is a Rust
panic with a backtrace, and CLAUDE.md has to explain it. `Result` from `main` with
`.expect("windres (from MinGW) must be on PATH to embed the icon")` is one line and says
what to do. The comments in that file are Portuguese; CLAUDE.md says new code is English.

### M7. Duplicate dependency majors in the tree
`cargo tree -d`: `image` 0.24 and 0.25, `png` 0.17 and 0.18, `raw-window-handle` 0.5 and
0.6, `windows-sys` 0.48/0.52/0.59/0.60/0.61, `webpki-roots` 0.26 and 1.0, `syn` 2 and 3.
Each pair is compiled and linked twice. The `image` one is ours: `Cargo.toml` asks for 0.24
while a dependency wants 0.25; `keyring` 2 (3 is current), `dirs` 5 (6 is current),
`ureq` 2 (3 is current), `quick-xml` 0.36 (0.41 is in the tree) and `egui` 0.28 (0.33 is
current) are upgrade debt that grows. No `rust-version` is declared either.
**Fix:** bump `image` first (it removes a whole codec set from the binary); plan an `egui`
upgrade as its own task, since `ui/tip.rs` and `prefs.rs::Card::reveal` carry workarounds for
0.28 bugs that a newer egui may have fixed or changed; declare `rust-version`.

### M8. Settings have no schema version
`src/config/mod.rs:552` `#[serde(default)]` on `Settings`. An older build opening a newer
file silently drops the keys it does not know, and saves without them. There is
`last_version` (`:829`), but it is used for the usage report, not for the file. A downgrade
after a failed update (which the updater can do, `update.rs:666-671`) loses settings.
**Fix:** a `version` key in `settings.toml`; refuse to save over a newer file, or keep a
`.bak` (see H3).

### M9. 167 `let _ =` and 12 `#[allow]`
Counts over `src/`. Most are deliberate (a status message that may be gone, a best-effort
rename). Some hide errors a user would want: the raw log write at `src/app/tab.rs:738`
(`let _ = log.write_raw(&bytes)`) means a full disk stops the transcript silently; the
parser advance at `:319` and `:395` ignores a result that is always `Ok`, which is fine.
**Fix:** grep them, and for each in `tab.rs`, `tabs.rs`, `config/`, `features/logging.rs`,
either log at `warn` or surface in the footer. Leave the UI ones.

### M10. Telnet has no read timeout and one lock around the codec
`src/pty/telnet.rs:410` (connect timeout only), `:453` (`codec.lock()` per read). A server
that accepts and goes silent is only noticed when the user closes the tab; the codec mutex
is shared with the writer, so a stalled write blocks reads. Low risk, but the reader thread
is also where a hostile server's option negotiation is answered (`:456-461`) with no limit
on reply size.
**Fix:** `set_read_timeout` with an idle counter that marks the session as stalled in the
footer; a cap on `replies` per chunk.

### M11. The App struct and `PanelState` keep growing
`src/app/mod.rs:100-200` (fields), `src/ui/panels.rs` (`PanelState` now carries `doctor`,
`doctor_page`, macro editors, theme editors, dialogs). Both are the dumping ground for every
new feature's state. Not a bug, but each new page adds fields that only one module reads.
**Fix:** a `pages: HashMap<Category, Box<dyn PageState>>`-style split, or at least one
struct per Settings page owned by `settings_view/`, so `panels.rs` stops knowing about the
Doctor.

### M12. The seven skins duplicate the same chrome
`src/ui/skin/{aqua,xp,win98,system,snes,winamp,tuned}.rs`, 850-1750 lines each. Title bar
button layout, tab strip geometry and the hover/press states are reimplemented per skin
with the shared parts in `skin/mod.rs` (1734 lines). A fix to one (as the "even title-button
spacing" fix in 0.2.0 was) has to be repeated.
**Fix:** when the next cross-skin fix comes, extract `TitleButtons`/`TabStripLayout` into
`skin/mod.rs` with per-skin drawing callbacks, rather than another copy.

### M13. `settings_view/mod.rs` is 3087 lines
Categories, rows, search, sidebar and page plumbing in one file. The Doctor page was added as
its own module (`doctor.rs`), which is the pattern to continue: move each category's rows into
`settings_view/<category>.rs` and leave `mod.rs` with `Item`, `page()`, the sidebar and
search.

### M14. The i18n table is a flat list of 1100 tuples
`src/i18n.rs`. Lookup is by English string; a changed English wording silently loses its
Portuguese. The duplicate-key test protects the table, not the call sites.
**Fix:** a test that walks `src/` for `tr("...")` literals and fails on one that is not in the
table (the reverse of the current test), so a renamed string is caught at test time.

### M15. The usage report and proxy credentials
`src/features/usage.rs:61` (`report`), `src/features/update.rs:13-20` (proxy user in
settings, password in the credential store). Read what `report` includes once more before
each release: it is sent off the machine. The username placeholder in the test at
`usage.rs:343` is fine. The proxy design is right (password never on disk).

## Low

### L1. `thread::sleep(8 ms)` loop in quake mode
`src/ui/quake.rs:616`. A wait loop on a thread for the drop-down animation; fine, but it is
the only sleep outside tests and session shutdown and deserves a comment saying why a
`wake()` is not enough.

### L2. 22 `unsafe` blocks in `quake.rs`, 10 in `tray.rs`
Win32 message hooks and window enumeration. Each has a SAFETY comment where read
(`desktop.rs:69`, `usage.rs:267`). Check that `quake.rs:795` and `:813` (`on_message`,
`on_main_message`) do not touch `App` state from the hook thread; they appear to post
messages only. Worth one dedicated read when touching quake again.

### L3. `pub` where `pub(crate)` would do
580 `pub fn/struct/enum` against 45 `pub(crate)`. `lib.rs` exposes every module as `pub`
so the integration tests can reach `term/` and `pty/`. The rest of `ui/` and `app/` need not
be public API; `cargo doc` documents all of it, and a private item link breaks the doc build
(CLAUDE.md). Narrow module by module when touching each.

### L4. Snapshot pictures are written, not compared
`src/ui/snapshot/mod.rs:25`, `:667-695`. Scenes render to `<folder>/<theme>/<scale>x/<scene>.png`
for the README; there is no golden comparison, so a layout regression in a skin is only seen
by eye. The pixel-exact lattice test exists for the grid; the chrome has none.
**Fix:** keep one low-resolution golden per skin under `tests/golden/`, compare with a
tolerance, update with an env var.

### L5. `README.md:180` and `README.en.md:177` say "as of 0.1"
The honesty sections list limits from 0.1; some are gone (tiled tabs, colours). Refresh at
0.2.1, and add the Doctor to the feature list.

### L6. No `SECURITY.md`, `CHANGELOG`, issue templates or Dependabot
The release notes in `packaging/release-notes.md` are rewritten each release, so there is no
history of changes outside Git tags. A `CHANGELOG.md` that the release step appends to, and
`.github/dependabot.yml` for `cargo` and `github-actions`, cost little.

### L7. `target-release2..7` folders
`/target-release*` is ignored by `.gitignore`, but seven of them exist on disk at ~1 GB
each. Delete after the user closes the running builds; the next build should go to
`target/release` again.

### L8. `build.rs` and a few older comments are in Portuguese
`build.rs:7-18`; CLAUDE.md says "New code is written in English". Translate when next
touched.

### L9. The Doctor's known limits (from its own docs and tests)
- On timeout only the check's own process is killed; children of a shell or PowerShell check
  survive (`src/features/doctor/run.rs`, `execute`). A Windows job object fixes it.
- A requirement on a check that applies to no OS blocks its dependents instead of being
  treated as `skip` (`src/features/doctor/mod.rs`, `unmet`).
- Fix tabs do not get `DOCTOR_*` or `MSYS=noglob` (`fix_profile`), unlike checks.
- Checks run one at a time; `Verify` is manual; no "Fix all".
- A fix has never been watched end to end on a real environment.

## Already good

Things seen while reading that the code gets right; do not redo them.

- Passwords: `Tab::pump` mutes the log across the password step (`src/app/tab.rs:729-736`,
  `:801-822` unmutes on a stall); `record_command` refuses during `WaitPassword`
  (`src/app/edit.rs:81`); pasted lines go through the same gate (`:284`). Keyring for both
  profile and macro secrets (`src/config/profile.rs:254`, `src/features/macros.rs:88`).
- Ctrl+click opens only `http://` and `https://` (`src/term/link.rs:24`), handed to the shell,
  never to a command line.
- The updater: rustls, a user agent, the size floor, the rename dance with rollback
  (`update.rs:663-671`), `clean_up()` at start, no self-install on macOS.
- Telnet: connect timeout, reader thread wakes the UI only on real data (`telnet.rs:466-472`).
- Scrollback is bounded and trimmed (`src/term/grid.rs:470-483`).
- OSC 52 (clipboard write) and hyperlinks are not implemented, so a remote host cannot
  write the clipboard (`src/term/parser.rs:168`).
- No `unwrap`/`expect` hot spots in non-test code: the only files with more than two are the
  Doctor's adversarial tests and three in `config/theme.rs`.
- No `TODO`/`FIXME` left in `src/`.
- The frame loop asks for frames only for a reason, each with a comment
  (`src/app/frame.rs:493-540`).
- `release.yml`: `permissions: contents: read` by default, `write` only on the draft job;
  `concurrency` without cancel; the version/tag agreement check; the single-`.exe` check;
  AppImage uploaded first for the updater; the published-release guard.
- Packaging scripts all start with `set -euo pipefail`.
- `.cargo/config.toml` caps jobs at 4 and the dev profile trims debug info, with the reason
  written down.
- `bin` has `test = false`, and the integration tests are one binary.
